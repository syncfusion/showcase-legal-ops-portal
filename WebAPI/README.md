# Legal Matter & Contract Management Portal — Backend API

A ASP.NET Core (.NET 10) Web API that powers the Legal Matter & Contract
Management Portal showcase. 

- **Stack:** .NET 10 · ASP.NET Core Minimal API · EF Core + Npgsql · Azure PostgreSQL (local Postgres for dev)
- **Architecture:** Clean Architecture — `Domain` → `Application` → `Infrastructure` → `Api`
- **Docs UI:** Swagger UI at `https://localhost:7051/swagger` (or `http://localhost:5123/swagger`)
- **OpenAPI doc (Microsoft.AspNetCore.OpenApi):** `https://localhost:7051/openapi/v1.json`

> ⚠️ Regulated-domain disclaimer: all matters, contracts, budgets, billing details,
> and names are strictly synthetic and do not constitute actual legal records, legal
> advice, or an attorney–client relationship.

## 1. Configure the database connection

The connection string is configured in `src/Api/appsettings.json` under `ConnectionStrings:DefaultConnection`. For local development, you can use a local PostgreSQL instance.

```json
"ConnectionStrings": {
  "DefaultConnection": "Host=localhost;Port=5432;Database=legal_matter_contract_portal;Username=YourUserName;Password=YourPassword"
}
```

To override the connection string using environment variables (recommended):

```powershell
# PowerShell — set for the current shell session
$env:ConnectionStrings__DefaultConnection = "Host=localhost;Port=5432;Database=legal_matter_contract_portal;Username=YourUserName;Password=YOUR_PASSWORD"
```

Create the development database (one-time):

```powershell
# From a psql-capable shell, or:
createdb -U postgres legal_matter_contract_portal
```

---

## 2. Run EF Core migrations

From the `WebAPI/` root directory, apply the migrations to create the database schema:

```powershell
dotnet ef database update `
  --project src/Infrastructure/LegalMatterContractPortal.Infrastructure.csproj `
  --startup-project src/Api/LegalMatterContractPortal.Api.csproj
```

---

## 3. Database Seeding

The database is automatically seeded with synthetic data during development. This process is idempotent and will skip seeding if data is already present.

**To re-seed the database from scratch:**

1. Drop the existing database:
```powershell
dotnet ef database drop -f `
  --project src/Infrastructure/LegalMatterContractPortal.Infrastructure.csproj `
  --startup-project src/Api/LegalMatterContractPortal.Api.csproj
```

2. Re-apply migrations and restart the API. The seeder will run automatically on startup.

---

## 4. Run the API with seeded data

From the `api/` folder:

```powershell
# HTTPS (preferred) — launches https://localhost:7051 + http://localhost:5123
dotnet run --project src/Api/LegalMatterContractPortal.Api.csproj

# HTTP only (no dev cert prompt)
dotnet run --project src/Api/LegalMatterContractPortal.Api.csproj --launch-profile http
```

On first launch the hosted seeder will log lines like:

```
info: Microsoft.EntityFrameworkCore.Database.Command[20101]
      Executed DbCommand (45ms) [Parameters=[], CommandType='Text', CommandTimeout='30']
      CREATE TABLE IF NOT EXISTS "__EFMigrationsHistory" ...
info: LegalMatterContractPortal.Api.Hosting.StartupSeederHostedService[0]
      Applying migrations and seeding the showcase database (deterministic seed 20260722)...
```

When seeding completes, browse to:

- **Swagger UI:** <https://localhost:7051/swagger> (or <http://localhost:5123/swagger>)
- **OpenAPI JSON (Microsoft.AspNetCore.OpenApi):** <https://localhost:7051/openapi/v1.json>
- **Root redirect:** <https://localhost:7051/> → `/swagger`

## 5. OpenAPI contract (manual export)

The live OpenAPI document is served by `Microsoft.AspNetCore.OpenApi` at `/openapi/v1.json`
while the API runs. To check a copy of the contract into `contracts/openapi/openapi.json`
(sourced by frontend service generators):

```powershell
# After the API is running:
iwr -UseBasicParsing "https://localhost:7051/openapi/v1.json" -OutFile contracts/openapi/openapi.json
```

The Swagger UI is generated by Swashbuckle at `/swagger/v1/swagger.json` as well — use
either. The contract contains **GET operations only**.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `NpgsqlException: ... password authentication failed` | Confirm `ConnectionStrings:DefaultConnection` credentials; use user secrets. |
| Startup seeder logged an error but API still runs | Check logs — Postgres may be unreachable. Fix connection, then restart. |
| Swagger UI shows no endpoints | You're not in `Development` — set `ASPNETCORE_ENVIRONMENT=Development`. |
| Dev cert prompt on first `https` run | `dotnet dev-certs https --trust` (one-time). |
| EF tools older than runtime warning | `dotnet tool update --global dotnet-ef`. |
| Re-seed didn't run after editing seeder | Seeder is idempotent — truncate tables (see step 3) or `dotnet ef database drop -f` then restart. |
